WikiRace · the design language

The design language

What every part of WikiRace is meant to look like, be called, and say — so that a new feature is a lookup rather than a judgement call, and the game looks like one thing. The prose version, with the measurements behind each decision, is in DesignLanguage.md.

This page is built out of the language it documents: every value below comes from the token block at the top of its source, which is the same block that goes into ui.html. If the two ever drift apart, this page stops looking right.

Colour

Unchanged. A base tier, and the tinted surfaces built from it. Switch the theme above and nothing here breaks — that is the standard the other dimensions are held to.

Shadows are built from --shadow, never a literal rgba: three places in the game hard-code rgba(0, 0, 0, .5) today and go muddy on the light themes. Player colours come from raceColors and nowhere else, so the timeline, the maps and the player boxes always agree on who is who.

Type

Four text sizes, four display sizes. Twenty-seven distinct sizes were measured across 140 declarations; forty-eight sat on half-pixels — 9.5, 10.5, 11.5, 12.5, 13.5 — scattered across unrelated components. Collapsing those is most of what this scale does.

Weights are 400 body, 600 emphasis, 700 heading. The 500, 650 and 800 in use today account for six declarations between them.

Radius, and elevation

Four roles. Thirteen values were in use to express them, and --radius: 10px — the only radius token that existed — was used three times and was already overloaded across two of the four.

--r-pill 999pxA token you read
--r-box 8pxControls, rows, notes, tips
--r-card 12pxA thing among its siblings
--r-panel 16pxThe container the rest sits in

--r-panel moves panels from 10px to 16px. Today a panel is rounded less than the cards inside it, which reads backwards — the container should be the softer shape. It is the one value here that moves for a reason other than consistency, and the first to look at if the standard ever feels wrong.

Elevation is three levels: --el-lift for a Tip, --el-float for a Panel, and an inset ring for focus. Both shadows are built from --shadow.

Motion

Three durations and two easings. --e-spring is for something that travels and lands — the theme switch's knob reaching its slot, someone arriving on your page, a checkpoint, the finish. Never for a hover, and never for a dialog simply appearing. Everything obeys prefers-reduced-motion.

--m-fast .12sState flicks: hover, press, toggle
--m-base .2sThe default: folds, fades, slides
--m-slow .6sCelebratory: splashes, fanfare
--e-springcubic-bezier(.4, 1.3, .5, 1) — things that travel and land

The seven pieces

Every surface in the game is one of seven. A new piece of UI is one of them, or you have found an eighth — and an eighth goes in this file before it goes in ui.html.

The base class sits alongside the feature namespace, so .card carries the shape and .lobby-card carries only what is particular to the lobby: <div class="card lobby-card">. No rename sweep, no build step, and an area nobody has converted keeps working untouched.

Pill — a standalone token you read

No back button Jazz (musical style) Mississippi River

Reach for it when

  • The thing is a single fact you scan rather than read.

Not when

  • Something sits inside it beyond a word and a number — that is a Card.
  • You want it to fill its width. Pills never stretch.

Control — something you operate

Rules

  • One primary per screen. Two means the screen has not decided what it is for.
  • The label says what will happen — “Start the race”, not “OK”.
  • Hover moves the ground over --m-fast. Nothing else moves.

Not when

  • It only reports state. Something that looks clickable but is not is worse than one that looks inert — use a Pill.

In the game

  • A Control is the element itself: a plain button, text field or select, with no class. Its text takes the size of wherever it sits.
  • Variants are .primary, .ghost, .danger and .big.

The stripe

  • A significant Row takes a left stripe in the colour of what makes it significant.
  • The stripe belongs to Rows. Notes never use it — it is the one piece of form that tells the two apart.

Rules

  • Every Row in a list is the same height unless its content genuinely differs.
  • Numbers sit right, in mono with tabular-nums.

Why centred

  • Row and Note are the same shape, so colour alone is a thin way to tell them apart — especially for anybody who does not see the colours.

Except

  • A Note that belongs to one control stays left-aligned at that control's edge, because centring detaches it from the field it is about.

Tip — floating, and pointing at what is under it

Bee — 11 clicks01:42

Rules

  • pointer-events: none unless it contains a Control.
  • It fades over --m-base. It does not slide, spring or scale.
  • Padding is tighter than a Note's on purpose, because a Tip is read in a glance.

Not when

  • It stays put and belongs to the layout — that is a Note.
  • It carries a sentence and points at nothing, like the toast — that is a Note that floats.
  • It has taken over the screen — that is a Panel.

Rules

  • Cards in a row are one object: same edges, same baselines, same inner padding.
  • Let content set the height; never stretch one to match another.
  • Cards do not get shadows. Depth comes from the ground, not from lifting every box.

The three spellings

  • .card, .lobby-card and .np-card were three implementations of this one idea, at radius 14 / 12 / 14.

Words

Anything a player can see is plain English. Every rule is transcribed from a line that already ships — this layer was already right, it just was not written down.

Name it their way“Everyone started somewhere different”, never “lost mode enabled”.
FailuresWhat happened, then what to do: “Couldn't find a pair in that language — try again”.
RefusalsSay why in the same breath: “Only article links count — that one's off-limits”.
SettingsA qualifying line, not a definition: “A real help — and arguably a cheat”.
LimitsAdvice, not validation: “Six checkpoints is plenty”.
CaseSentence case, no shouting. Labels and buttons take no full stop.
Two messages, one ruleThe server's message and the browser's say the same thing. The browser check exists only to be faster.

The test: read it aloud to somebody who has never played. If you have to explain a word, it is the wrong word.

Derived by measuring ui.html — 6,504 lines, 1,282 of them CSS. The rules about how the game works, rather than how it looks, live in .claude/notes/decisions.md. Four things are deliberately not covered: the article itself, which keeps Wikipedia's own colours and type; the route maps and timeline, which are data drawings; illustrations, such as the miniature screens behind the mode picker's cards; and the big moments — the countdown and the splashes — which are loud on purpose. The interface around any of them, and any message shown with them, does follow this page.
